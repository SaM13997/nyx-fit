## Problems & blockers

- Initial `npx tsc --noEmit` failed on existing errors across workouts, weight tracking, and login navigation. The user approved minimal fixes; the final whole-project check passes.
- Initial build failed because the installed dependencies lacked Rollup's Linux-native package. A normal installation attempt encountered the existing better-auth peer conflict. With the user's approval, `npm ci --ignore-scripts --legacy-peer-deps` restored the lockfile-defined installation. Package manifests and lockfiles were not edited by this task.
- Initial test execution exposed an incomplete jsdom `matchMedia` mock and concatenated day-pill accessible text. Both were corrected; all tests pass.
- Plain `git diff --check` flagged existing CRLF endings. The check passes with `cr-at-eol` enabled; existing file line endings were retained.
- Production build emits non-blocking large-chunk, dependency unused-import, and Nitro compatibility-date warnings.
- Live email/Google authentication and live Convex writes were not exercised. Authentication and mutation boundaries are mocked in the regression tests; the real motion components and form run in jsdom. Real-device visual and assistive-technology verification remains unperformed.

No outstanding implementation P0/P1 findings were identified in self-review.

## Assumptions and confidence

- **High:** the referenced implementor prompt is approval to implement the review-converged plan.

- **High:** the existing standalone authentication behavior is retained, with the optional onboarding email callback replacing navigation when supplied.
- **Medium:** deployed provider configuration will complete the OAuth round trip as simulated. Provider configuration was not tested live.

## Self-review and simplification pass

- **P1, resolved:** pre-existing missing formatter, mismatched frontend weight IDs, and missing workout mutation arguments were corrected with user approval.
- **P2, resolved:** native day-pill names now separate the number and unit; the email input has an explicit accessible name.
- **P2, resolved:** logger auto-advance is cancelled when the exiting step loses presence, preventing a late timer from overriding Back.
- **P2, resolved:** onboarding action hover colors retain stronger white-text contrast; auth overrides are scoped to onboarding.
- **P2, outstanding verification:** live authentication and real-device accessibility/visual checks remain to be performed.
- `delete:` removed the carousel and orphaned imports from login; that route shrank from 187 to 58 lines, **net: -129 lines**.
- `native:` native fieldsets, legends, radios, buttons, session storage, and timers provide the flow mechanics.
- `shrink:` building and preview reuse the same plan rendering for the skeleton crossfade; progress stays inline.
- `yagni:` static lookup, existing mutation hook, existing auth providers, and existing motion library satisfy the approved scope without a new generation service or dependency.

The final self-review has zero open implementation P0/P1 findings. Accepted plan trade-offs remain: one silent retry, no failure-specific Done copy, client-only goal staging, and loss of staging if the OAuth tab is destroyed.
